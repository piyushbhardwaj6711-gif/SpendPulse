# 📉 Customer Churn Prediction — End-to-End ML Web App

Predicts whether a telecom customer will churn, explains **why** using SHAP,
and serves the result through an interactive Streamlit UI.

## Architecture

```
Raw CSV (Kaggle)
      │
      ▼
src/train.py ──► Clean → Encode → Split → Scale → Train (LogReg + RF)
      │                                              │
      │                                    Evaluate & select best model
      │                                              │
      ▼                                              ▼
models/ (model.pkl, scaler.pkl, columns.pkl, background.pkl, ...)
      │
      ▼
app.py (Streamlit) ──► User inputs → Preprocess → Predict → SHAP waterfall
```

**Key design choice:** `columns.pkl` stores the exact one-hot-encoded column
order from training. At inference, `app.py` re-encodes the single-row user
input and `reindex`-es it against this saved list (filling missing dummy
columns with 0), guaranteeing the feature space always matches what the
model was trained on — even though the UI only exposes a subset of raw
fields at the top level.

## Dataset

[Telco Customer Churn — Kaggle](https://www.kaggle.com/datasets/blastchar/telco-customer-churn)
(7,043 rows, 21 columns). Download `WA_Fn-UseC_-Telco-Customer-Churn.csv` and
place it in `data/`.

## Model

Two baselines are trained and compared on the held-out 20% test split:

| Model | What it's good for |
|---|---|
| Logistic Regression | Interpretable coefficients, fast baseline |
| Random Forest | Captures non-linear interactions, usually stronger recall |

Selection criterion: **highest ROC-AUC, Recall as tiebreaker** — in churn
prediction, missing an actual churner (false negative) is more costly than
flagging a loyal customer (false positive), so recall on the positive class
is weighted heavily during model comparison.

The winning model's `metrics.json` (accuracy, precision, recall, F1, ROC-AUC
for both models) is saved to `models/` after every training run.

## Run Locally

```bash
# 1. Clone and enter the project
git clone https://github.com/<your-username>/churn-prediction-app.git
cd churn-prediction-app

# 2. Create a virtual environment (recommended)
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Add the dataset
#    Download WA_Fn-UseC_-Telco-Customer-Churn.csv from Kaggle into data/

# 5. Train the model (generates everything in models/)
python src/train.py

# 6. Launch the app
streamlit run app.py
```

The app opens at `http://localhost:8501`.

## Deploy to Streamlit Community Cloud (Free)

1. **Push to GitHub**
   ```bash
   git init
   git add .
   git commit -m "Initial commit: churn prediction app"
   git branch -M main
   git remote add origin https://github.com/<your-username>/churn-prediction-app.git
   git push -u origin main
   ```
   Since `models/` is gitignored by default in most `.gitignore` templates,
   either:
   - commit the trained `.pkl` files directly (simplest for a small demo repo), **or**
   - add a `setup.sh`/build step that runs `python src/train.py` on deploy (requires the CSV to also be committed or fetched at build time).

   For a portfolio project, the simplest reliable path is to commit
   `data/*.csv` and `models/*.pkl` directly so the deployed app has
   everything it needs with zero extra steps.

2. **Go to** [share.streamlit.io](https://share.streamlit.io) and sign in with GitHub.

3. **Click "New app"**, select your repo, branch (`main`), and set the main
   file path to `app.py`.

4. **Deploy.** Streamlit Cloud installs `requirements.txt` automatically and
   gives you a public URL like `https://your-app-name.streamlit.app`.

5. Add that URL to your resume/portfolio — done.
